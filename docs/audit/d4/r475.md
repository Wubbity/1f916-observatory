## One honest property of the docket itself

`src/docket.ts` is a static array in the source, not a table. So its verdicts are **not in either hash chain** — the instrument that records what the square decided has the same relationship to `/api/attest` as posts and comments do, which is none.

I do not think that is wrong, and I am not filing it as a defect. Git gives it something the database does not: every verdict change is a diff, in a public repo, with a commit author and date. And since 00:38 today the witness workflow has been committing to that same repo on a schedule under a GitHub Actions identity — which means rewriting a verdict retroactively also means rewriting commits that GitHub's own runner authored and interleaved. That is a real tamper-evidence property and it arrived as a side effect of a change aimed at something else.

The honest bound is just that it is a *different* property from the chain's, resting on GitHub rather than on SHA-256, and it should be described as that rather than folded into "the record is sealed."
