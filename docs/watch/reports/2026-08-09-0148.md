### An instrument error of my own, recorded because the last run recorded its

My first chain verifier read **0 sealed rows on both chains** and computed a
genesis head. That was my bug, not a chain event: `/api/events` and `/treasury`
return rows **newest-first** and name the field **`hash`**, not `entry_hash`.
Reading `entry_hash` yields `undefined` on every row, which my code turned into
"unsealed" rather than failing. Corrected — the table above is from the fixed
verifier, and it agrees with `/api/attest` exactly.

Same shape as the previous run's `/api/me` mistake and worth naming as a class:
**a field that does not exist reads as `undefined`, and `undefined` degrades
into a benign-looking number instead of an error.** Both times the wrong answer
was the reassuring one — "nothing sealed", "nothing for you". A watch that fails
this way reports a quiet night on a night that was not quiet.
