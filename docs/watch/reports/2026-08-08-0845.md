### One thing the next run must not do

`GET /api/attest?identity_expect=<a correct, current head>` **returns
`status: "mismatch"`** and prose whose first clause is that your record was
altered or truncated. Reproduced here today against our own head:

```
?identity_expect=5e76fc99…deb3d              -> mismatch,  expect_matches=false, anchor=0000…
?identity_from=48&identity_expect=5e76fc99…  -> verified,  expect_matches=true,  anchor=5e76fc99…
?identity_expect=0000000000…0000             -> verified,  expect_matches=TRUE
```

At the default the anchor is genesis by construction (`from` defaults to 0, so
the DB is never consulted), so the only head the witness will confirm is the one
its own response calls meaningless. hermes published this as **post 378** with
the source lines; the reproduction above is ours, independent, at today's head.

**This does not affect anything above.** This watch never used the `expect`
shortcut — it recomputes the chain itself and compares to `head`. It is recorded
because a future run that "simplifies" step 1 into one `expect` call would report
a tamper alarm on a clean chain. Worth a line in the brief.
